# Решение: свести всё в один репозиторий AI-Dubbing

Дата: 2026-10-10. Согласовано с владельцем проекта.

## Решение

Единый репозиторий — **AI-Dubbing**. Он остаётся домом для всей работающей логики,
тестов, четырёх venv'ов, sfx-библиотеки и проверенных артефактов.
**AI-DUB-app архивируется как источник идей**: его ядро переносится один раз, отдельный
проект больше не поддерживается.

Причина: две папки с пересекающимся смыслом ничего не связывало, вся проверенная
реальность лежит в AI-Dubbing, а «чистое разделение» выгодно только когда обе стороны
зрелые. Объём незавершённой работы от выбора не меняется — меняется только адрес кода.

Роль AI-DUB-app в итоге: **не продукт, а заготовка ядра**, которую мы забираем.

## Что переносим из AI-DUB-app (и почему это лучше, чем в cli.py)

| модуль | зачем |
|---|---|
| `app/core/pipeline.py` | исполнение этапов: восстановление `RUNNING` после падения, перепроверка `COMPLETED` по артефакту, громкая ошибка записи состояния, защита от повторного входа |
| `app/core/pipeline_state.py` | атомарная запись состояния (`tmp` + `fsync` + `replace`) |
| `app/core/stage_handler.py` | интерфейс `StageHandler` / `StageOutcome` + локатор артефакта — в него ложатся адаптеры движка |
| `app/core/stage_dependencies.py`, `pipeline_stage.py` | граф этапов (расширить до реальных 12 стадий движка) |
| `app/core/pipeline_context.py`, `projects/project*.py` | изоляция по проекту (свои каталоги на каждое видео) |
| `app/models/*` | `ProjectConfig`, `MediaInfo`, `SpeechSegment`, `Character`, `Transcript` |
| `app/services/video_analyzer.py`, `audio_extractor.py` | реальные ffprobe/ffmpeg и **единственный манифест с отпечатком исходника** |
| `tests/` (37) | переносятся как есть, это тесты ядра |

## Что не переносим

- `app/main.py` (пустой) и `json_store.py` (мёртвый код);
- `config_store.load()` — пересоздаёт под-конфиги вызовом `default()` трижды;
- `analysis_service` с кэшем «только по существованию файла»;
- планировщик `for stage in PipelineStage` (порядок перечисления вместо топосортировки);
- проверку артефакта `exists() and size > 0`;
- `PipelineState.load`, который **молча обнуляет весь прогресс** при дрейфе схемы.

## Целевой вид

```
AI-Dubbing/
  scripts/      движок, 11 этапов (как есть, отдельные venv'ы, контракт AI_DUB_*)
  core/         перенесённое ядро: состояние, этапы, прогресс, проекты
  adapters/     по одному тонкому адаптеру на этап: subprocess + AI_DUB_*
  gui/          появится позже, тонким слоем над core/
  tests/        тесты движка (67) + тесты ядра
  test_run_1200s/  изолированный стенд (не трогать)
```

## Обязательный харденинг ядра (иначе повтор старого дефекта)

1. **Манифест артефакта** с отпечатком входа (путь, размер, mtime_ns) и хэшем параметров
   этапа; несовпадение = артефакта нет.
2. **Перенести инварианты** из `scripts/integrity.py` на уровень ядра: полнота перевода,
   соответствие TTS-манифеста репликам, покрытие речи, счётчики.
3. **Реальный прогресс** (внутри этапа, а не 0.0/1.0) для GUI и ETA.
4. **Отмена, таймауты, ретраи** — сейчас нет ни одного.
5. **Загрузка состояния**: версия схемы, громкий отказ или карантин вместо тихого сброса.

## Порядок работ (каждый шаг проверяем без GUI)

1. Скопировать ядро и тесты в `core/`, ничего не удаляя в AI-DUB-app; прогнать его 37 тестов.
2. Добавить версию схемы и громкую загрузку состояния; тест на дрейф схемы.
3. Заменить проверку артефакта на манифест с отпечатком; тест «подменённый артефакт отвергнут».
4. Перенести инварианты `integrity.py`; тесты на реальных артефактах 1200 s (они уже есть).
5. Написать 9 адаптеров (asr, align, diarize, merge, translate, dialogue, tts, fit_tts, mix, mux, sfx, ambience), по одному тесту на адаптер.
6. Собрать цепочку в ядре на 150-секундном клипе и сравнить результат с прогоном через `cli.py`.

## Ограничения

Не ломать проверенный конвейер: `test_run_1200s/` и одобренный MP4 не трогать до шага 6.
Никаких новых зависимостей, модели остаются локальными, коммитов без отдельного разрешения.
`AI-DUB-app` не изменять — только читать как источник.
